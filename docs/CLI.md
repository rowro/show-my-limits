# Show My Limits в терминале

Утилита `sml` работает без графического приложения, Python, GTK и WebView.
Если используете DEB из следующего релиза, команда `sml` устанавливается вместе с приложением. Для других установок скачайте архив `sml_…zip` для своей ОС и архитектуры из [Releases](https://github.com/rowro/show-my-limits/releases), распакуйте его и запустите `./sml --help` (Windows: `sml.exe --help`).
Чтобы вызывать `sml` из любого каталога на macOS/Linux, поместите исполняемый файл в пользовательский каталог из `PATH`, например `~/.local/bin`, и убедитесь, что каталог есть в `PATH`. На Windows добавьте каталог с `sml.exe` в пользовательскую переменную `Path`.
На macOS действуют те же ограничения Gatekeeper, что и для неподписанного приложения.

```sh
sml setup --host api.anthropic.com
sml trust
sml run --host api.anthropic.com
```

`setup` установит официальный mitmproxy с проверкой SHA-256 и создаст сертификат только для указанных серверов (`--host` можно повторять; без него берутся серверы из настроек). Ключ CA не сохраняется, поэтому для другого сервера понадобится новый сертификат. Существующий сертификат не заменяется. Исключение — CA прошлой версии, которому не доверяет ни одно проверенное хранилище ОС, или неполное хранилище: его каталог переносится в `certificates-previous` (ключ не удаляется), а для сервера создаётся новый сертификат.
`trust` на macOS и Windows устанавливает сертификат в хранилище текущего пользователя только по явной команде. ОС может запросить подтверждение.
На Linux `sml trust` только выводит команды **системной** установки доверия для Ubuntu/Debian; их нужно выполнить отдельно. Этому CA смогут доверять другие пользователи и приложения компьютера. После установки `sml doctor` проверяет наличие точного CA в системном пакете Debian, но клиент может использовать другое хранилище. Для других дистрибутивов используйте их штатное хранилище CA.
После настройки доверия и включения захвата полностью перезапустите клиент Claude, в том числе открытые сессии Claude Code, и отправьте сообщение.
Без заголовков лимитов от сервера показателей не будет.

| Команда | Действие |
| --- | --- |
| `sml run` | Захват с сервером и процессами из настроек приложения |
| `sml run --host gateway.example` | Задать сервер только на этот запуск |
| `sml run --host gateway.example --process Code` | Дополнительно перехватывать именованный процесс |
| `sml watch` | Смотреть уже работающий захват GUI или другого CLI |
| `sml status` | Один снимок текущих показателей |
| `sml status --json` | Текущие показатели в JSON, `null` при отсутствии живого захвата |
| `sml doctor` | Каталоги, путь к перехватчику, отпечаток и оставшийся срок сертификата |
| `sml doctor --share` | Отчёт для поддержки с категорией последнего события захвата, без путей, имён серверов и трафика |

`sml doctor --share` один раз читает локальное состояние помощника, CA, доверия и живого захвата. Он ничего не устанавливает, не меняет настройки и не отправляет отчёт в сеть: текст появляется только в терминале. Перед отправкой его всё равно можно просмотреть. Для подробностей текущего соединения используйте `sml run` или `sml watch`; `sml status --json` содержит имена серверов и не предназначен для публикации без проверки.

По умолчанию перехватываются `Claude` и `claude`. Параметр `--process` можно повторять.
При запуске `sml run` печатает выбранный сервер и имена процессов. Сначала показывается ожидание готовности помощника; после неё отсутствие запроса, ответа или заголовков лимитов объясняется отдельным сообщением.
`--host` и `--process` не изменяют сохранённые настройки приложения.
Ctrl+C завершает захват, запущенный этой командой. В режиме просмотра чужой захват продолжает работать.
Если захват уже запущен новым приложением или другим CLI, `run` подключается к нему как просмотрщик.
Не запускайте одновременно старую версию приложения без поддержки CLI.

GUI и CLI используют один каталог `io.github.rowro.showmylimits`, одну установку mitmproxy и один сертификат.
Порядок установки не важен: GUI использует подготовленные CLI файлы и наоборот.
Настройки: macOS `~/Library/Application Support/…`, Windows `%APPDATA%\…`, Linux `$XDG_CONFIG_HOME/…` (по умолчанию `~/.config/…`).
Данные на Linux лежат в `$XDG_DATA_HOME/…` (по умолчанию `~/.local/share/…`).
Существующие сертификаты не заменяются автоматически. Для первого запуска GUI остаётся пройти подтверждение шагов мастера.

На Linux нужны поддерживаемое ядро (6.8+) и разрешение на локальный сетевой захват; mitmproxy запросит пароль через терминал.
Не запускайте всю утилиту от root: это создаст отдельное хранилище сертификатов.
Сообщения и токены не сохраняются; настройки Claude и системного прокси не меняются.

CLI обновляется заменой исполняемого файла из нового релиза. Встроенный updater относится к графическому приложению.
