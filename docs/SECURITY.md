# Безопасность локального CA

Show My Limits перехватывает HTTPS только для сервера, указанного при настройке. Сервер известен лишь на этом шаге, поэтому сертификат создаётся после него.

## Формат: CA без хранимого ключа

Новые установки GUI и `sml setup` создают CA в памяти:

- CA ограничен Name Constraints (критическое расширение): разрешены только DNS-имена настроенных серверов, любые IP-адреса запрещены. Срок CA 400 дней.
- Тем же ключом подписывается один лист ECDSA P-256 для этих серверов (serverAuth, 397 дней), после чего ключ CA удаляется. Он не записывается на диск ни в каком виде.
- На диске остаются публичный CA (для доверия) и `leaf-chain.pem` (ключ листа, лист и CA, права `0600`). mitmproxy получает лист через `--certs`; его собственный CA лежит в отдельном `untrusted-confdir`, которому никто не доверяет, а `--allow-hosts` не пропускает другие хосты.

Укравший файлы получает только ключ листа для настроенного сервера: выпустить сертификат для другого сайта нельзя. Name Constraints — вторая линия обороны. Их соблюдение проверено в OpenSSL, Python ssl, Node, macOS Security.framework, Windows CryptoAPI/Schannel и Chrome на всех трёх ОС ([прототип и результаты](../tools/leaf-ca/README.md), воркфлоу `ca-constraints.yml`). Системный curl macOS (LibreSSL 3.3.6) сравнивает имена как строковый суффикс; Claude Desktop и Claude Code им не пользуются.

Цена: смена сервера и истечение листа требуют нового CA и нового подтверждения доверия. Пока новому CA не доверяют, приложение пересоздаёт его само; доверенный CA заменяется только через явный перевыпуск. Перед использованием хранилище проверяется целиком: цепочка, подписи, совпадение ограничений с SAN листа, соответствие ключа листу, отсутствие ключа CA и символьных ссылок.

Claude Code читает системные корни один раз при запуске. После установки или смены доверия нужно перезапустить Claude Desktop и открытые сессии Claude Code, иначе старые процессы отклонят сертификат.

## Доверие и хранение

- macOS: новые установки через GUI и CLI добавляют доверие в область текущего пользователя. Версии до этого изменения могли добавить CA в System/Admin; обновление приложения не удаляет старое доверие.
- Windows: автоматическая установка использует Current User Root. Linux: инструкции для Debian/Ubuntu добавляют CA в системный набор доверия; команда `sml trust` только печатает инструкции. Некоторые клиенты используют отдельное хранилище CA.
- Новые хранилища CA на macOS/Linux публикуются с правами каталога `0700` и файлов `0600`. Уже существующие файлы только проверяются; приложение не меняет их автоматически. Это не защищает от процессов того же пользователя и резервных копий.
- Старые установки используют CA mitmproxy старого формата: ключ CA хранится на диске и подходит для выпуска сертификата любого сайта. Такой CA продолжает работать, проверяется по прежним правилам (обычные файлы, совпадение сертификатов, соответствие RSA-ключа) и не заменяется при обновлении; настройки предупреждают о нём и предлагают явный перевыпуск.
- Повреждённое хранилище явно обозначается в GUI и `sml doctor`; отчёт для обмена содержит только категорию, без путей и ключа.
- В настройках «Захват» показаны SHA-256 действующего CA и обнаруженная область доверия. На macOS проверяются домены User/Admin, на Windows — Current User/Local Machine Root, на Debian/Ubuntu — точное совпадение сертификата с системным PEM bundle. Отдельные хранилища клиента и другие Linux-дистрибутивы эта проверка не охватывает. Предупреждение не удаляет доверие и не перевыпускает CA.
- Для обмена диагностикой используйте отчёт из настроек или `sml doctor --share`. Обычный `sml doctor` показывает локальные пути и отпечаток CA.
- Настройки показывают дату окончания CA и предупреждают за 30 дней. `sml doctor` печатает оставшиеся дни, а отчёт для обмена — только категорию срока без даты и отпечатка.

## Перевыпуск старых CA

Старый CA заменяется только по явному действию пользователя. Новый CA создаётся рядом в новом формате, пользователь подтверждает доверие, пробный захват должен получить свежие квоты, затем приложение переключается и отдельно предлагает удалить доверие к старому CA по точному отпечатку. Автоматической замены CA при обновлении нет.

См. [макет пользовательского пути](CA-ROTATION-FLOW.md) и текущие задачи в [WORKLIST.md](WORKLIST.md).
