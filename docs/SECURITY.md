# Безопасность локального CA

Show My Limits использует локальный mitmproxy CA для HTTPS-захвата выбранного сервера. Закрытый ключ хранится в каталоге данных пользователя и не отправляется приложением наружу. `--allow-hosts` ограничивает захват в работающем процессе, но **не ограничивает возможности украденного ключа CA**: mitmproxy может выпускать сертификаты для других имён. Чтобы перехватить чужое соединение, атакующему также нужен путь для подмены трафика.

## Доверие и хранение

- macOS: новые установки через GUI и CLI добавляют доверие в область текущего пользователя. Версии до этого изменения могли добавить CA в System/Admin; обновление приложения не удаляет старое доверие.
- Windows: автоматическая установка использует Current User Root. Linux: инструкции для Debian/Ubuntu добавляют CA в системный набор доверия; команда `sml trust` только печатает инструкции. Некоторые клиенты используют отдельное хранилище CA.
- Новые хранилища CA на macOS/Linux публикуются с правами каталога `0700` и файлов `0600`. Уже существующие файлы только проверяются; приложение не меняет их автоматически. Это не защищает от процессов того же пользователя и резервных копий.
- Перед использованием хранилища проверяются обычные файлы без символьных ссылок, наличие PEM-блока закрытого ключа и точное совпадение встроенного сертификата с публичным CA. Проверка не доказывает криптографическое соответствие ключа сертификату; это остаётся задачей для следующей итерации. При несовпадении существующие файлы не заменяются.
- В настройках «Захват» показаны SHA-256 действующего CA и обнаруженная область доверия. На macOS проверяются домены User/Admin, на Windows — Current User/Local Machine Root, на Debian/Ubuntu — точное совпадение сертификата с системным PEM bundle. Отдельные хранилища клиента и другие Linux-дистрибутивы эта проверка не охватывает. Предупреждение не удаляет доверие и не перевыпускает CA.
- Для обмена диагностикой используйте отчёт из настроек или `sml doctor --share`. Обычный `sml doctor` показывает локальные пути и отпечаток CA.

## Ограничение CA и перевыпуск

Name Constraints может ограничить имена в сертификатах, но [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280#section-6.1.1) допускает, что ограничения в самом trust anchor не применяются. [Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/policy/resources/templates/policy_definitions/Miscellaneous/EnforceLocalAnchorConstraintsEnabled.yaml) отдельно описывает своё поведение для локальных корней. Поэтому расширение нельзя считать защитой для всех клиентов без проверки macOS, Windows, Linux и Claude. [mitmproxy](https://docs.mitmproxy.org/stable/concepts/certificates/) допускает пользовательский CA, но совместимость генерации сертификатов и смены сервера также нужно проверить.

Старые CA будут перевыпускаться только по явному действию пользователя после проверки нового формата. Порядок: создать новый ключ и сертификат рядом со старым, подтвердить новое доверие, проверить захват, переключить приложение, затем отдельно предложить удалить доверие к старому CA по точному отпечатку. При ошибке пользователь должен иметь возможность вернуться к старому состоянию. Автоматической замены CA при обновлении нет.
