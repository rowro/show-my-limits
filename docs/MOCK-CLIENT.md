# Проверка перехвата без Claude

Тестовый клиент — отдельный исполняемый файл `claude` (`claude.exe` на Windows). Он делает настоящие HTTPS-запросы, а тестовый echo-сервер возвращает заголовки лимитов. Корпоративная учётная запись, API-ключ и установленный Claude не нужны.

## Запуск

1. Скачайте архив своей ОС из **Actions → Mock Claude → успешный запуск → Artifacts**, распакуйте его в отдельную папку. Не заменяйте им настоящий Claude и не добавляйте его в PATH.
2. Пройдите мастер подключения Show My Limits, включая установку сертификата и доверия.
3. Укажите сервер **`httpbingo.org`**, сохраните настройки и включите перехват. После проверки верните свой обычный сервер.
4. Откройте терминал в папке с тестовым клиентом и запустите:

macOS / Linux:

```sh
chmod +x ./claude
./claude --scenario normal
```

Windows PowerShell:

```powershell
.\claude.exe --scenario normal
```

Клиент повторяет запрос каждые 5 секунд, пока не нажмёте Ctrl+C. Для одного запроса добавьте `--count 1`. После перезапуска перехватчика перезапустите и тестовый клиент. Файл должен называться именно `claude` / `claude.exe`, чтобы работал стандартный фильтр процессов.

## Сценарии

Остановите клиент и запустите его с другим `--scenario`:

| Сценарий | Осталось за 5 часов | Осталось за 7 дней |
| --- | --- | --- |
| `normal` | 65% | 58% |
| `low` | 8% | 5% |
| `blocked` | 0% | 0% |
| `weekly-blocked` | 75% | 0% |
| `progress` | Остаток уменьшается на 5 п.п. с каждым запросом | На 1 п.п. с каждым запросом |
| `missing` | Ответ без заголовков лимитов | Последние показатели не обновляются |

Сбросы задаются относительно запуска клиента: через 90 минут и 3 дня. `blocked` и `weekly-blocked` возвращают статус квоты `rejected` внутри HTTP 200; это не имитация HTTP 429. Тело ответа не является ответом модели.

Клиент проверяет, что сервер действительно вернул ожидаемые заголовки. В терминале отображаются PID, полученные показатели и издатель TLS-сертификата. При перехвате издатель обычно соответствует CA Show My Limits (`limits-mitmproxy`). Сам по себе успешный HTTPS-запрос ещё не доказывает перехват: показатели должны появиться в Show My Limits.

## Доверие и сеть

По умолчанию используется системное доверие к сертификатам. Проверка TLS не отключается. Если системное доверие настроено неверно, клиент завершится с ошибкой — это часть проверки установки.

Для отдельной диагностики можно явно добавить публичный CA приложения: `--ca /path/to/mitmproxy-ca-cert.pem`. Используйте только файл сертификата, без закрытого ключа. Такой запуск проверяет перехват, но **не подтверждает правильность системной установки сертификата**.

Интернет нужен: публичный [httpbingo.org](https://httpbingo.org/) получает только синтетические значения квот в query-параметрах. Токены, переписка и корпоративные адреса не используются. Недоступность сервиса или изменение его поведения тоже могут вызвать ошибку. Параметр `--endpoint` позволяет указать совместимый HTTPS `/response-headers` сервер с доверенным сертификатом; домен в Show My Limits должен ему соответствовать.

Клиент игнорирует переменные HTTPS_PROXY/HTTP_PROXY: проверяется именно прозрачный захват процесса. Он использует TCP/HTTP 1.1; проверка HTTP/2, потоковых ответов и особенностей доверия реального Claude Desktop/IDE всё равно потребует отдельных проверок. Успешный тест не гарантирует совместимость со всеми клиентами Claude.

На Linux для Local Capture по-прежнему нужны поддерживаемое ядро и права. Виртуальная машина должна иметь доступ в интернет; клиент и Show My Limits запускаются внутри одной гостевой ОС.

## Сборка из исходников

Нужен Go 1.23+; внешних библиотек нет:

```sh
cd tools/mock-claude
go test ./...
go build -o claude .
# Windows: go build -o claude.exe .
```

Не используйте `go run` для проверки фильтра: имя временного процесса может отличаться от `claude`. CI собирает macOS arm64/x64, Windows x64 и Linux arm64/x64. Эти артефакты предназначены для тестирования и не входят в установщик Show My Limits.

## Диагностика IPv6

Если без перехвата HTTPS работает, а с ним появляется `Network is unreachable` на IPv6, проверь тот же сценарий через `./claude --ipv4 --scenario normal --count 1`. Этот флаг есть в клиенте v2. Он ограничивает TCP-соединение клиента IPv4, сохраняя исходное имя сервера, SNI и проверку TLS. Системные настройки IPv6 не меняются. Результат такого теста подтверждает только IPv4-путь.
