# План: безопасность, Debian, диагностика и CLI

Порядок соответствует риску для пользователя. Отмечать задачу завершённой только после указанных проверок. Существующие CA, доверие и пользовательские данные не менять автоматически.

## P0 — безопасность CA

- [x] Для **новой установки через macOS GUI** использовать связку и домен доверия текущего пользователя вместо системной связки и домена Admin. Сборка и модульные тесты прошли; реальное подтверждение macOS ещё не проверено.
- [ ] Проверить права на каталог CA и закрытый ключ после создания GUI и CLI на macOS/Linux. Для новых Unix-хранилищ добавлена установка 0700/0600, для существующих — предупреждение без изменения файлов. Прямой запуск закреплённого mitmproxy 12.3.1 на macOS создал каталог `0700` и четыре файла `0600`; в Debian 13 ARM64 получены такие же права. Остаётся проверить конечный путь GUI и CLI после публикации хранилища. Права файла не исключают копирование ключа Time Machine или другим процессом того же пользователя.
- [ ] Проверить криптографическое соответствие закрытого ключа и сертификата CA до использования. В Rust добавлена проверка RSA-ключа через `ring`, совпадения публичного и встроенного сертификатов, отсутствия символьных ссылок и ограничения размера файлов. Тесты с совпадающей и несовпадающей RSA-парами прошли; реальные временные CA закреплённого mitmproxy 12.3.1 прошли проверку на macOS ARM64 и в изолированной Debian 13 ARM64. Осталось собрать Windows и подтвердить конечные пути GUI/CLI. Временные тестовые ключи удалены.
- [x] Сообщать о повреждённом хранилище CA до захвата: GUI и обычный `sml doctor` показывают причину без замены файлов; отчёты для обмена используют фиксированную категорию. Проверено модульными тестами на несовпадающей паре.
- [x] Новый формат CA: ключ CA не хранится, Name Constraints ограничивают CA настроенными серверами, mitmproxy получает лист через `--certs`. Ограничения проверены в CI на macOS, Windows и Ubuntu x64/arm64 и вручную на macOS с Claude Desktop и Claude Code (`tools/leaf-ca/README.md`). Перенесено в GUI и CLI; мастер создаёт сертификат после выбора сервера. На macOS 2026-11-24 Rust-путь проверен: установка доверия кнопкой мастера, `macos_trust::is_trusted` для CA с ограничениями, захват `local` с `--certs` и недоверенным confdir, лимиты от корпоративного сервера в Claude Desktop. Остаются Windows и Linux.
- [x] Переход со старых версий: недоверенный или неполный CA переносится в `certificates-previous` вместо предложения доверять ему (GUI и `sml setup`); доверенный CA без единого полученного ответа с лимитами заменяется без пробного захвата. Проверено на macOS 2026-11-24 (отладочная сборка с отдельным идентификатором): старый недоверенный CA перенесён при запуске, флаг доверия сброшен, кнопка удаления старого ключа сработала. Сценарий «доверен, но лимитов не было» нативно не проверялся.
- [ ] Спроектировать обнаружение и **добровольное** удаление старого доверия в macOS System/Admin и Linux системном хранилище. Read-only проверка точного сертификата добавлена для macOS User/Admin, Windows Current User/Local Machine и Debian/Ubuntu системного PEM bundle; GUI показывает область доверия и отпечаток. В текущей ветке после переключения старый CA остаётся в `certificates-previous`, UI просит удалить доверие по отпечатку, а ключ удаляется только по отдельной кнопке после проверки доступных хранилищ и, на Linux, исходных `.crt` файлов. Ручные инструкции и проверку на реальных ОС ещё нужно доработать; отдельные trust stores клиента не охвачены. Никакой автоматической очистки при обновлении.
- [ ] Сократить срок действия CA и сделать добровольный перевыпуск **старых** CA с новым ключом. Новые установки и перевыпуск создают CA нового формата (400 дней, ключ CA не хранится, лист на 397 дней). Текущая ветка реализует подготовку нового CA рядом со старым, отдельное доверие, пробный захват, переключение только после свежих квот и явную очистку. Файловое переключение и восстановление после прерывания покрыты модульным тестом. Полный пользовательский путь ещё не проверен нативно; особенно нужны отмена доверия, ошибки пробного захвата, Windows/Linux сборки и реальный HTTPS-клиент на каждой ОС. Не заменять CA или его ключ автоматически.
- [x] Показывать срок CA до отказа захвата: дата в настройках с предупреждением за 30 дней, число дней в `sml doctor`, категория без точной даты в отчёте для обмена. Модульные проверки GUI, CLI и Rust прошли; визуально проверить в нативном окне при целевом smoke-тесте.
- [x] Добавить к релизной проверке сценарии: чистая установка, существующий System/Admin CA, отмена системного запроса, CLI и GUI с одним CA, работа клиента после смены доверия. Критерии и запрет публикации без проверенного перевыпуска записаны в `docs/RELEASING.md`; сами проверки остаются обязательными перед релизом.

### Текущий этап перевыпуска — не готов к выпуску

Срез на 2026-11-24: реализация сохранена в отдельной ветке. Локально прошли Rust-тесты GUI и CLI, `npm test`, `npm run build`, тесты Python addon и `npm run check:release`. Эти проверки подтверждают сборку и логику отдельных переходов, но не работу доверия и захвата в целевых нативных сеансах. Следующая точка работы — безопасный возврат после переключения, затем проверка полного пути на macOS, Windows и Debian 13. Релиз пока заблокирован.

- [x] Пробный захват использует новый CA и допускает переключение только после свежих квот из этого запуска; при неудачном старте делается попытка вернуть старый захват.

## P1 — диагностика

- [ ] macOS: «Запускаем захват» висит, затем тайм-аут 90 секунд. Причина по исходникам mitmproxy_rs: Mitmproxy Redirector запрашивает сетевое расширение и ждёт одобрения пользователя без тайм-аута, ничего не печатая. GUI теперь читает `systemextensionsctl list`, показывает экран «Нужно разрешение macOS» с кнопкой открытия настроек и не обрывает запуск, пока одобрение ожидается (плюс 60 секунд после). Подтвердить на Mac, где расширение ещё не одобрено; кнопку открытия «Объекты входа и расширения» проверить на macOS 14 и 15+.

- [ ] Проверить в нативном Linux окне новый контекст «Выбранный сервер → Изменить» на экранах запуска, ожидания и ошибки. В браузерном макете переход открывает вкладку «Захват» с сохранённым сервером.
- [ ] Проверить в нативном Linux окне «Повторить запуск» после сбоя графического запроса прав: действие заново запускает захват и, если sudo требует пароль, открывает системный запрос. Браузерный макет перехода в состояние запуска проверен.
- [ ] Разобрать отдельный сбой Linux GUI: после «Запустить захват» через 90 секунд появляется «Перехватчик не подтвердил готовность», захват снова выключен. Claude при этом отвечает, но трафик не перехватывается. Проверить запрос sudo/zenity, права и запуск упакованного помощника, появление heartbeat; воспроизвести на Debian 13. При тайм-ауте теперь показывается уже распознанная категория ошибки помощника вместо общего сообщения.
- [ ] Разобрать случай: `sml` не показывает квоты после перезапуска Claude Desktop/IDE и отправки сообщений. CLI теперь печатает выбранный сервер и имена процессов, предупреждает об отсутствии точного CA в системном PEM bundle Debian/Ubuntu, различает запуск помощника и готовый захват, отсутствие запроса к выбранному серверу, запрос без ответа и ответ без заголовков; нужна проверка в реальном Linux-сеансе с клиентом.
- [ ] Добавить безопасную диагностику GUI/CLI: отчёт GUI и `sml doctor --share` используют фиксированные категории запроса, ответа без квоты, сертификата, TLS и сети без путей, имён серверов и трафика. Модульные тесты подтверждают отсутствие адреса сервера в GUI-отчёте и отклонение произвольного текста из локального состояния CLI. Остаётся проверить на реальном сбое в Linux-сеансе.
- [ ] Сделать вывод для обращения в поддержку с просмотром перед копированием: GUI и `sml doctor --share` добавлены; проверить в нативном окне и сценариях ошибок на целевых ОС.
