# План: безопасность, Debian, диагностика и CLI

Порядок соответствует риску для пользователя. Отмечать задачу завершённой только после указанных проверок. Существующие CA, доверие и пользовательские данные не менять автоматически.

## P0 — безопасность CA

- [x] Для **новой установки через macOS GUI** использовать связку и домен доверия текущего пользователя вместо системной связки и домена Admin. Сборка и модульные тесты прошли; реальное подтверждение macOS ещё не проверено.
- [ ] Проверить права на каталог CA и закрытый ключ после создания GUI и CLI на macOS/Linux. Для новых Unix-хранилищ добавлена установка 0700/0600, для существующих — предупреждение без изменения файлов; остаётся проверить права после реального запуска mitmproxy на обеих ОС. Права файла не исключают копирование ключа Time Machine или другим процессом того же пользователя.
- [ ] Проверить криптографическое соответствие закрытого ключа и сертификата CA до использования. В Rust добавлена проверка RSA-ключа через `ring`, совпадения публичного и встроенного сертификатов, отсутствия символьных ссылок и ограничения размера файлов. Тест с временными совпадающей и несовпадающей RSA-парами на macOS прошёл; реальный CA закреплённого mitmproxy 12.3.1 прошёл проверку в изолированной Debian 13 ARM64. Осталось собрать Windows и подтвердить на реальной установке macOS/Linux. Временный тестовый CA удалён.
- [x] Сообщать о повреждённом хранилище CA до захвата: GUI и обычный `sml doctor` показывают причину без замены файлов; отчёты для обмена используют фиксированную категорию. Проверено модульными тестами на несовпадающей паре.
- [ ] Исследовать ограничение CA по DNS через Name Constraints на реальных клиентах macOS, Windows и Linux. RFC 5280 допускает, что ограничения в самом trust anchor не применяются; Chromium отдельно оговаривает их проверку. Нельзя считать расширение достаточной защитой без испытаний. Проверить выпуск сертификатов mitmproxy, пользовательские хосты, смену сервера и совместимость с TLS-проверкой клиентов. Только после этого выбрать формат CA и безопасный путь замены существующего сертификата.
- [ ] Спроектировать обнаружение и **добровольное** удаление старого доверия в macOS System/Admin и Linux системном хранилище. Read-only проверка точного сертификата добавлена для macOS User/Admin, Windows Current User/Local Machine и Debian/Ubuntu системного PEM bundle; GUI показывает область доверия и отпечаток. На Linux другие trust stores и отдельное хранилище клиента не охвачены. Удаление, проверка рабочего нового доверия и полный путь замены ещё не реализованы. Никакой автоматической очистки при обновлении.
- [ ] Сократить срок действия CA и сделать добровольный перевыпуск **старых** CA с новым ключом. Для новых установок генератор создаёт RSA CA на 365 дней без дополнительной P12-копии ключа. Закреплённый mitmproxy 12.3.1 создал такой CA в изолированной Debian 13 ARM64; Rust проверил ключ, сертификат и структуру. Через явный HTTP-прокси mitmproxy синтетический запрос к `https://httpbingo.org/get` вернул HTTP 200 при успешной TLS-проверке новым CA (curl `ssl_verify_result=0`); лог подтвердил перехват GET. Тест не охватывает прозрачный захват и доверие ОС. Осталось проверить реальный HTTPS-клиент на macOS, Windows и Linux, затем создать новый CA рядом, проверить доверие и захват до удаления доверия к старому. Не заменять CA или его ключ автоматически.
- [x] Показывать срок CA до отказа захвата: дата в настройках с предупреждением за 30 дней, число дней в `sml doctor`, категория без точной даты в отчёте для обмена. Модульные проверки GUI, CLI и Rust прошли; визуально проверить в нативном окне при целевом smoke-тесте.
- [ ] Добавить к релизной проверке сценарии: чистая установка, существующий System/Admin CA, отмена системного запроса, CLI и GUI с одним CA, работа клиента после смены доверия.

## P1 — Debian 13 и доступность окна

- [ ] Воспроизвести на Debian 13 в X11 и Wayland: пункт «Открыть Show My Limits», левый клик по трею и клик вне панели. Записать последовательность событий фокуса и проверить, остаётся ли процесс живым. В изолированном Xvfb/Openbox приложение оставалось запущенным, но `stalonetray` не смог принять его AppIndicator-значок (XEmbed BadWindow); клик по панели не был проверкой действия приложения. Нужен реальный совместимый трей/GNOME-сеанс.
- [ ] Исправить гонку между меню трея и `Focused(false)`, сохранив обычное скрытие по клику вне панели и поведение перетаскивания в Linux. Отложенное открытие после закрытия меню и защита первого события потери фокуса внесены; требуется реальная проверка Debian 13 и Ubuntu.
- [ ] Проверить запуск DEB на графической Debian 13; отдельно проверить помощника, `zenity`, запрос прав и реальный захват. DEB текущей ветки собран в Debian 13 ARM64. Поле `Depends` содержит `sudo`, `zenity` и нативные библиотеки GTK/WebKit; установка в одноразовый контейнер поставила обе команды, встроенный `sml --version` выполнился. Остаются графический запрос прав и захват в реальном сеансе. Предупреждение Ayatana о deprecated API само по себе не означает отказ приложения.

## P1 — диагностика

- [ ] Проверить в нативном Linux окне новый контекст «Выбранный сервер → Изменить» на экранах запуска, ожидания и ошибки. В браузерном макете переход открывает вкладку «Захват» с сохранённым сервером.
- [ ] Проверить в нативном Linux окне «Повторить запуск» после сбоя графического запроса прав: действие заново запускает захват и, если sudo требует пароль, открывает системный запрос. Браузерный макет перехода в состояние запуска проверен.
- [ ] Разобрать отдельный сбой Linux GUI: после «Запустить захват» через 90 секунд появляется «Перехватчик не подтвердил готовность», захват снова выключен. Claude при этом отвечает, но трафик не перехватывается. Проверить запрос sudo/zenity, права и запуск упакованного помощника, появление heartbeat; воспроизвести на Debian 13. При тайм-ауте теперь показывается уже распознанная категория ошибки помощника вместо общего сообщения.
- [ ] Разобрать случай: `sml` не показывает квоты после перезапуска Claude Desktop/IDE и отправки сообщений. CLI теперь печатает выбранный сервер и имена процессов, предупреждает об отсутствии точного CA в системном PEM bundle Debian/Ubuntu, различает запуск помощника и готовый захват, отсутствие запроса к выбранному серверу, запрос без ответа и ответ без заголовков; нужна проверка в реальном Linux-сеансе с клиентом.
- [ ] Добавить безопасную диагностику GUI/CLI: отчёт GUI и `sml doctor --share` используют фиксированные категории запроса, ответа без квоты, сертификата, TLS и сети без путей, имён серверов и трафика. Модульный тест подтверждает отсутствие адреса сервера при сетевой ошибке. Остаётся проверить на реальном сбое в Linux-сеансе.
- [ ] Сделать вывод для обращения в поддержку с просмотром перед копированием: GUI и `sml doctor --share` добавлены; проверить в нативном окне и сценариях ошибок на целевых ОС.
